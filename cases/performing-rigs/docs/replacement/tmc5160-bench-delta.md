Timing clarification for step4: T §4.3 p25 specifies internal-oscillator SCK maximum4MHz, mode3,10ns CS-to-clock and SDI setup/hold minima; for asynchronous clocking, SCK HIGH/LOW exceed tCLK+10ns and CS HIGH exceeds2tCLK+10ns. Account for actual driver clock, loading and filtering. Legacy2MHz API request is not a measured safe setup and does not establish those margins.

IOIN oracle detail: T §6.1 p34 lists read0x04, VERSION31:24, SD_MODE6, CFG6/DCO5, DRV_ENN4, DCIN3, DCEN2, DIR1, STEP0. It does **not** expose SPI_MODE as a bit. Version alone is insufficient; correlate known powered inputs and deselection control. SPI_STATUS occupies the first received byte (T §4.1.2 p24); retain reset/error flags separately from the32-bit IOIN response. This IOIN pair is a **document-defined proposed bench request**, not a claim it executed in the legacy trace (legacy reads0x6f).

Reset clarification: T §25 p119 distinguishes TMC power/undervoltage reset from MCU reboot, which can leave configuration active. VCC is unmonitored. Do not cycle VCC_IO while MCU drives inputs HIGH; the datasheet's reset method requires LOW digital inputs to avoid back-power. Any board reset procedure must be engineered for the shared devices/rails. No new reset-by-trial procedure is authorized here.

Diagnostic correction: DRV_STATUS29/30 are open-load A/B flags with validity conditions (T §6.5.5 p56), not a reliable connector-presence test. Current zero field is not bridge-off; CHOPCONF.TOFF0 disables bridges per T pp51–52, but sending that word depends on working communication and is not a substitute for independent pre-test containment. Read-only SPI safety still depends on step1.
